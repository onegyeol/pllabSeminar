## 주요 개념
- 함수형 프로그래밍 언어: Elixir는 Erlang VM(BEAM) 위에서 동작하는 함수형 언어로, 동시성 및 분산 처리에 최적화되어 웹 애플리케이션 개발에 적합하다.
- 가독성 높은 문법: Ruby와 유사한 깔끔한 문법을 채택하고 있으며, 패턴 매칭과 파이프 연산자(|>) 등의 기능을 제공하여 코드 생산성과 유지보수성을 높인다.
- 경량 프로세스: Erlang의 Actor 모델을 활용해 수만 개의 경량 프로세스를 동시 실행할 수 있고, 프로세스 간 메시지 passing으로 부작용 없이 병행 처리가 가능하다.
- 강력한 도구: 프로젝트 관리 도구인 Mix, 패키지 관리자 Hex, 대화형 쉘 IEx 등 개발 편의를 위한 풍부한 툴링을 제공한다.
- OTP 프레임워크: Supervisors, GenServer 등 OTP 라이브러리를 통해 고가용성 및 장애 복원력을 갖춘 시스템을 구축할 수 있다.

### 익명함수

익명 함수는 이름 없이 정의하는 함수로, `fn` ... `end` 구문을 사용하여 만들 수 있다. 이렇게 정의한 함수를 변수에 할당하고, `.( )` 표기법으로 호출한다.

```
sum = fn (a, b) -> a + b end
IO.puts(sum.(2, 3))   # 출력: 5
```
또한 Elixir에서는 익명 함수를 `&` 기호로 축약 표현할 수 있다. 매개변수는 `&1`, `&2`처럼 참조하며, 아래 코드는 동일한 덧셈 기능을 더 간결하게 표현한 것이다.
```
sum = &(&1 + &2)
IO.puts(sum.(2, 3))   # 출력: 5
```

### 툴링 (디버깅, 테스트, 포맷팅 등)

#### 디버깅

코드 실행 중에 디버깅이 필요하면 `IEx.pry`를 사용하여 해당 지점에서 인터랙티브 셸을 열 수 있다. 아래 예에서는 함수 내부에 `IEx.pry()`를 넣어 호출 시 실행을 일시 중단하고 변수 `a`, `b` 등의 값을 실시간으로 확인할 수 있다 (이 코드를 실행한 뒤 `Calc.sum/2`를 호출하면 Pry 세션이 시작됨).

```
defmodule Calc do
  def sum(a, b) do
    require IEx; IEx.pry()
    a + b
  end
end
```
또한 간단한 디버깅에는 `IO.inspect/2`로 변수나 표현식의 값을 출력하는 방법도 흔히 사용된다.

#### 테스트

Elixir의 ExUnit 프레임워크를 통해 손쉽게 단위 테스트를 작성할 수 있다. 테스트 모듈에서는 `use ExUnit.Case`를 사용하고, `test "설명"` 블록 안에 `assert` 등을 통해 기대 결과를 검증한다.

```
defmodule MathTest do
  use ExUnit.Case

  test "1 + 1은 2가 된다" do
    assert 1 + 1 == 2
  end
end
```
위와 같이 테스트 코드를 작성한 후 터미널에서 `mix test`를 실행하면 모든 테스트가 수행되며, 성공 혹은 실패 여부가 출력된다.

#### 포맷팅

Elixir에서는 `mix format` 명령으로 코드 스타일을 자동으로 정렬해준다. 예를 들어, 들쑥날쑥한 들여쓰기나 띄어쓰기가 있는 코드를 포맷터로 정돈하면 아래와 같이 일관된 형태로 바뀐다.
```
# 포맷팅 전 (서식이 잘못된 코드):
defmodule Example do
def sum(a,b), do: a+b
end

# 포맷팅 후 (mix format 적용):
defmodule Example do
  def sum(a, b), do: a + b
end
```

### 태스크와 에이전트

#### 태스크 (Task)

태스크는 별도의 프로세스로 함수를 비동기로 실행한 후 그 결과를 나중에 받아볼 수 있게 해주는 기능이다. 긴 연산을 태스크로 수행하면 메인 프로그램 흐름을 막지 않고 동시에 진행할 수 있다. 아래 코드에서는 `Task.async/3`로 오래 걸리는 함수를 백그라운드에서 실행하고, `Task.await/1`로 결과를 가져온다.

```
defmodule Example do
  def double(x) do
    :timer.sleep(2000)
    x * 2
  end
end

task = Task.async(Example, :double, [2000])
# ... (다른 작업들을 수행)
result = Task.await(task)
IO.puts("두 배 결과: #{result}")   # 출력: 두 배 결과: 4000
```

#### 에이전트 (Agent)
에이전트는 상태를 갖는 백그라운드 프로세스를 추상화한 것으로, 여러 프로세스가 해당 상태에 접근하고 수정할 수 있도록 한다. `Agent.start_link/2`로 에이전트를 시작하면서 초기 상태를 설정하고, `Agent.update/2`로 상태를 변경하며, `Agent.get/2`로 현재 상태 값을 가져올 수 있다.

```
# 에이전트를 시작하고 리스트 [1, 2, 3]을 초기 상태로 설정
{:ok, agent} = Agent.start_link(fn -> [1, 2, 3] end)

# 에이전트 상태에 값 추가 (리스트에 4 추가)
Agent.update(agent, fn state -> state ++ [4] end)

# 에이전트의 현재 상태 값을 가져와 출력
current = Agent.get(agent, fn state -> state end)
IO.inspect(current, label: "Agent state")   # 출력: Agent state: [1, 2, 3, 4]
```
에이전트를 시작할 때 이름을 지정하면 (`Agent.start_link(fn -> initial_state end, name: YourName)` 형태), PID 대신 이름으로 해당 에이전트에 접근할 수도 있다.

### 장점
- 동시성에 강함: Actor 모델 기반으로 멀티프로세스 동시성 처리에 뛰어나 실시간 고부하 시스템에 적합합니다.
- 안정성: Erlang/OTP의 철학인 "Let it crash"와 Supervisors를 통해 고장 복구 능력이 우수한 견고한 애플리케이션을 만들 수 있습니다.
- 생산성: 불변성과 함수형 패러다임 덕분에 사이드 이펙트가 줄어들어 버그가 감소하고, 가독성 높은 코드를 작성할 수 있습니다.
- 웹 개발 친화적: Phoenix 같은 고성능 웹 프레임워크가 있어 실시간 웹서비스나 API 서버 개발에 효율적입니다.

### 단점
- 생태계 규모: JavaScript나 Python 등에 비해 라이브러리/프레임워크 생태계가 좁은 편이어서 선택지가 제한적일 수 있습니다.
- 학습 난이도: 익숙하지 않은 함수형 프로그래밍 개념(재귀, 고阶 함수 등)과 Actor 모델을 익히는 데 학습 곡선이 있습니다.
- 성능 한계: CPU 집약적인 작업의 경우 C/C++ 같은 저수준 언어보다는 성능이 떨어질 수 있음을 감안해야 합니다.
- 배포 제약: BEAM VM 위에서 구동되므로 일반 호스팅 환경에서는 직접 실행이 어렵고, 릴리즈/배포 과정에 추가적인 툴을 사용해야 합니다.

### 주요 개념
- 절차적 저수준 언어: C 언어는 시스템 소프트웨어와 임베디드 시스템 개발에 주로 사용되는 절차적 프로그래밍 언어로, 메모리 관리와 포인터 등을 통한 저수준 하드웨어 제어가 가능합니다.
- 컴파일 언어: 소스 코드를 기계어로 컴파일하여 실행하며, 하드웨어에 가까운 수준에서 동작하므로 실행 속도가 매우 빠릅니다. 또한 컴파일러 최적화를 통해 성능을 극대화할 수 있습니다.
- 메모리 모델: 스택과 힙 구조 개념이 중요하며, 함수 호출 시 스택 메모리를 사용하고 동적으로 필요한 경우 힙에 할당합니다. C에서는 malloc/free로 메모리를 직접 할당 및 해제해야 합니다 (가비지 컬렉션 없음).
- 이식성: 표준 규격을 준수하는 다양한 컴파일러가 존재하여, 코드 수정 없이도 여러 플랫폼에 재컴파일하여 실행할 수 있을 만큼 이식성이 뛰어납니다
- 역사적 중요성: 1970년대에 유닉스(Unix) 운영체제를 C로 구현한 이후 시스템 프로그래밍의 표준이 되었으며, 많은 현대 언어(C++, Objective-C 등)에 영향을 준 중요한 역사적 언어입니다.

### 장점
- 높은 성능: 저수준 메모리 접근과 최소한의 런타임 오버헤드로 매우 빠른 실행 속도와 효율적인 메모리 사용이 가능합니다.
- 세밀한 제어: 포인터를 비롯한 저수준 기능으로 메모리와 하드웨어 자원을 세밀하게 제어할 수 있어, 시스템 최적화나 드라이버 작성 등 성능이 중요한 프로그램에 적합합니다.
- 이식성과 경량성: 핵심 문법이 작고 표준 라이브러리가 경량이라서 플랫폼 이식성이 뛰어나고 임베디드처럼 제약된 환경에서도 동작합니다.
- 풍부한 활용처: 수십 년 간 쌓인 방대한 라이브러리와 커뮤니티 지식을 보유하고 있어 운영체제, 컴파일러, 게임 엔진 등 광범위한 분야에서 표준 역할을 해왔습니다.

### 단점
- 메모리 관리 부담: 개발자가 수동으로 메모리를 관리해야 하므로 잘못된 포인터 연산, 메모리 누수, 버퍼 오버플로 등의 치명적인 오류를 일으키기 쉽습니다.
- 안전성 부족: 경계 검사 없는 배열, 형 변환의 위험 등 언어 차원의 안전장치가 부족하여 보안 취약점이 발생할 여지가 있습니다.
- 생산성 저하: 저수준 코드를 일일이 작성해야 하고 표준 라이브러리가 한정적이어서, 고급 언어에 비해 개발 생산성이 낮고 구현 시간이 오래 걸립니다.
- 복잡한 문법 요소: 포인터 개념이나 전처리기 매크로 등은 초심자가 이해하기 어려우며, 디버깅 또한 어렵습니다. 규모가 큰 프로그램에서는 관리가 까다로울 수 있습니다.

### 주요 개념
- React 기반 프레임워크: Next.js는 React를 기반으로 한 오픈 소스 프론트엔드 프레임워크로, **SSR(서버사이드 렌더링)**과 **SSG(정적 사이트 생성)**를 지원하여 초기 로드 속도와 사용자 경험을 향상시킵니다.
- SEO 향상: SSR/SSG로 미리 렌더된 HTML을 제공하기 때문에 검색 엔진 크롤러가 페이지 내용을 쉽게 읽을 수 있어 SEO에 유리한 웹 애플리케이션을 구축할 수 있습니다.
- 파일 기반 라우팅: /pages 디렉토리 구조만으로 자동으로 라우팅이 설정되며, 링크 이동이나 동적 라우팅 등도 편리하게 구현됩니다. 별도의 라우터 설정 없이 파일 생성으로 페이지 추가가 가능합니다.
- 다양한 내장 기능: 코드 스플리팅 및 번들 최적화가 자동으로 이루어지고, 이미지 최적화(next/image), API Routes(서버리스 함수), 데이터 페칭 메소드(getStaticProps, getServerSideProps 등)와 같은 기능들이 프레임워크에 내장되어 있어 개발자의 생산성을 높입니다. 
- 전체 스택 지원: Node.js 환경에서 동작하므로, React 컴포넌트로 UI를 구축함과 동시에 서버 측 렌더링이나 API 구현까지 풀스택 개발을 하나의 프로젝트로 수행할 수 있습니다.

### 장점
- SEO 및 초기 성능: SSR/SSG로 초기 페이지를 렌더링하여 초기 로드 시간이 빠르고 검색 엔진에 잘 노출되는 웹사이트를 만들 수 있습니다.
- 개발 효율성: 파일 기반 라우팅, 자동 코드 분할 등 설정보다 규칙에 집중하는 구조로 개발이 단순하고 빠릅니다. 필요한 기능이 미리 갖춰져 있어 보일러플레이트 코드가 줄어듭니다.
- React 활용: 기존 React 라이브러리, 컴포넌트를 그대로 활용하면서도 Next.js만의 이미지 최적화, 정적 파일 제공 등의 추가 혜택을 얻을 수 있습니다.
- 배포 편의: Vercel 등과 연계하여 손쉽게 배포 및 호스팅이 가능하고, 빌드 결과물을 정적 파일로 만들어 CDN 캐싱을 활용하는 등 배포 전략을 최적화할 수 있습니다.

### 단점
- 불필요한 복잡성 가능: 아주 단순한 SPA에는 Next.js의 SSR/SSG 기능이 오히려 과한 구조일 수 있으며, 이 경우 불필요한 러닝커브와 구성이 추가됩니다.
- 프레임워크 학습 필요: 기본 React 외에 Next.js 특유의 **디렉토리 구조와 함수(getStaticProps 등)**를 익혀야 하므로 초기 학습 비용이 있습니다.
- 빌드 시간 및 비용: 정적 사이트 생성의 경우 페이지 수가 많으면 빌드 시간이 길어지고, SSR을 사용하면 요청 시마다 서버 렌더링을 하므로 서버 자원 사용이 늘어날 수 있습니다.
- 제약된 유연성: Next.js의 방식에 맞춰 개발해야 하므로, React만 사용할 때보다 구조적인 제약을 느낄 수 있습니다 (예: 사용자 정의 서버 구성은 Next.js에 맞게 제한됨).

## 주요 개념
- JavaScript 런타임: Node.js는 Chrome V8 엔진 기반의 자바스크립트 런타임 환경으로, 브라우저 바깥에서 JavaScript를 실행할 수 있게 해줍니다. 이를 통해 JS를 사용하여 서버 프로그램을 작성할 수 있습니다.
- 이벤트 기반 비동기 I/O: 이벤트 중심의 논블로킹 I/O 모델을 채택하여, 동시에 많은 연결을 처리할 때도 성능이 뛰어난 고병렬성 서버를 구현할 수 있습니다. (I/O 작업 동안 스레드가 블로킹되지 않고 다른 이벤트를 처리함)
- 싱글 스레드 구조: Node.js 애플리케이션은 단일 스레드 이벤트 루프로 동작하지만, 내부적으로는 libuv를 통해 스레드 풀을 활용하여 파일 시스템 접근 등의 작업을 처리합니다. 이러한 구조로 경량 프로세스에서 많은 동시성을 얻어냅니다.
- 풍부한 패키지 생태계: 기본 제공 모듈 외에 npm(Node Package Manager)을 통해 수많은 오픈소스 패키지를 사용할 수 있어서, 데이터베이스 연동, 웹 프레임워크(예: Express) 등 대부분의 기능을 라이브러리로 손쉽게 추가할 수 있습니다.
- 광범위한 활용: 주로 웹 서버와 API 서버 구축에 사용되지만, 실시간 애플리케이션(채팅 서버 등), CLI 도구, 데스크톱 앱(Electron 기반) 등 JavaScript로 구현 가능한 거의 모든 분야에 활용되고 있습니다.

## 몽고 DB와 연동
```
const MongoClient = require('mongodb').MongoClient;
MongoClient.connect("mongodb://localhost:27017", function(err, db) {
  if (err) throw err;
  const dbo = db.db("mydatabase");
  const collection = dbo.collection("users");

  // 나이(age)가 18 이상인 사용자들만 조회 (이름과 나이 필드만 선택)
  const query = { age: { $gte: 18 } };
  collection.find(query, { projection: { name: 1, age: 1, _id: 0 } })
    .sort({ age: 1 })    // 나이 기준 오름차순 정렬
    .limit(5)            // 결과를 상위 5개로 제한
    .toArray((err, docs) => {
      if (err) throw err;
      console.log("조회된 문서들:", docs);
      db.close();
    });
});
```
기본적인 질의 예제로, JavaScript 객체를 사용해 MongoDB 쿼리 조건을 만드는 방법을 보여준다.

### 장점
- 언어 통일: 서버를 JavaScript로 구현하므로 프론트엔드와 백엔드에서 같은 언어를 사용할 수 있어 개발자가 맥락 전환 없이 풀스택을 다룰 수 있습니다.
- 높은 처리량: 논블로킹 I/O와 이벤트 루프 덕분에 I/O-bound 작업에서 높은 동시 접속 처리량을 보여주며, 실시간 데이터 처리가 필요한 애플리케이션(예: 채팅, 스트리밍)에 적합합니다.
- 풍부한 생태계: npm을 통한 세계 최대 규모의 패키지 생태계를 활용하여, 필요한 기능을 갖춘 모듈을 손쉽게 찾아 사용함으로써 개발 생산성을 높일 수 있습니다. 
- 경량 개발: Node.js 자체가 가벼운 런타임이며, JSON 등을 다루기 편해 REST API 등의 신속한 프로토타이핑에 유리합니다. 또한 서버 실행/재시작이 빠르고 환경 설정이 비교적 단순합니다.

### 단점
- CPU 연산에 취약: 이벤트 루프가 싱글 스레드로 동작하기 때문에, CPU를 많이 사용하는 연산이 있으면 전체 처리 속도가 떨어집니다. (워커 스레드나 분산 처리를 통해 보완해야 함)
- 복잡한 비동기 코드: 콜백 패턴이나 Promise 체인 등 비동기 코드 구조가 복잡해질 수 있어, 코드 가독성과 에러 처리가 어려운 문제가 있습니다 (최근 async/await 도입으로 많이 개선됨).
- 메모리/자원 관리: 가비지 컬렉션으로 메모리를 관리하지만, 장기간 실행되는 서버에서는 메모리 누수를 주의해야 하고 V8 엔진 특성상 메모리 사용량이 높아질 수 있습니다.
- 콜백 지옥 & 퀄리티 차이: npm 패키지에 의존하는 경향이 높은데, 일부 패키지는 품질이 낮거나 업데이트가 중단되기도 하여 의존성 관리에 신경써야 합니다. 또한 초기에는 콜백 중첩으로 인한 소위 "콜백 지옥" 문제가 있었지만, 현재는 많이 완화되었습니다.

### 주요 개념
- 간결한 컴파일 언어: Go(골랑)는 Google에서 설계한 정적 타입의 컴파일 언어로, 문법이 단순하고 컴파일 속도가 빨라 대규모 프로젝트에서도 개발 효율을 높일 수 있습니다. C 언어의 성능과 파이썬의 생산성을 절충한 느낌의 언어입니다.
- 메모리 관리: 가비지 컬렉션을 내장하여 메모리를 자동으로 관리해주며, 개발자는 메모리 누수나 해제에 대해 신경 쓸 부분이 줄어듭니다. 포인터를 지원하지만 pointer 연산은 제한적이며, Null 포인터 역참조에 대한 안전장치는 없습니다.
- 동시성 지원: Go의 가장 큰 특징 중 하나는 **고루틴(goroutine)**이라 불리는 경량 스레드와 **채널(channel)**을 통한 통신입니다. 고루틴은 수만 개를 생성해도 성능이 뛰어나며, 채널로 고루틴 간 데이터를 주고받아 병행 프로그래밍을 간소화합니다.
- 구조체와 인터페이스: 객체지향의 클래스 개념 대신 **구조체(struct)**로 데이터를 표현하고, **인터페이스(interface)**로 행동 규약을 정의합니다. 임베디드 필드로 **구성(composition)**을 활용하며, 다형성은 인터페이스 만족으로 얻습니다 (명시적 implements 키워드 없이, 메서드 집합으로 구현).
- 단일 바이너리 산출: Go는 외부 의존성 라이브러리까지 모두 정적 링크해 하나의 실행 파일을 생성합니다. 별도의 VM 없이 네이티브 코드로 컴파일되며, 배포 시 추가 요구사항이 없어 배포와 실행이 매우 간편합니다.

### 예제 코드
```
package main

import (
    "fmt"
    "time"
)

func printMessage(msg string) {
    fmt.Println(msg)
}

func main() {
    go printMessage("고루틴에서 실행")       // 새 고루틴에서 함수 실행
    fmt.Println("메인 함수에서 실행")
    time.Sleep(time.Second)           // 프로그램이 바로 종료되지 않도록 대기
}

```
### 장점
- 효율성과 성능: 컴파일러 최적화를 통해 빠른 실행 성능을 내며, 가비지 컬렉션이 있지만 대체로 지연 시간이 짧아 서버 사이드 애플리케이션에 적합합니다. 또한 컴파일 속도가 매우 빨라 개발 피드백 루프가 짧습니다.
- 동시성의 용이함: 고루틴과 채널 덕분에 스레드 생성/관리 부담 없이 손쉬운 동시성 프로그래밍이 가능하고, 수많은 동시 작업을 간단한 코드로 구현할 수 있습니다.
- 깔끔한 문법과 구조: 문법이 단순하고 코드 포맷터(gofmt)가 제공되어 일관성 있는 코드 스타일을 유지할 수 있습니다. 따라서 팀 협업 시 코드 가독성과 유지보수성이 높습니다.
- 쉬운 배포: 별도의 런타임 설치 없이도 동작하는 스탠드얼론 실행 파일을 생성하므로, Docker 이미지나 배포 파일의 크기가 작고 배포 과정이 단순합니다.

### 단점
- 제한된 추상화: 제네릭 프로그래밍 등이 Go 1.18에서 도입되었지만 기능이 제한적이며, 템플릿 메타프로그래밍이나 예외 처리 같은 고급 언어 기능은 지원하지 않습니다. 필요한 경우 반복 코드를 생성하거나 인터페이스로 우회해야 합니다.
- 런타임 GC 오버헤드: 가비지 컬렉터가 주기적으로 동작하므로, 시스템 프로그래밍 언어나 실시간성이 중요한 분야에서는 GC로 인한 지연이 문제가 될 수 있습니다.
- 상대적으로 적은 라이브러리: 웹 개발 생태계는充실하지만, Python/Ruby 등에 비해 서드파티 라이브러리나 프레임워크의 다양성은 부족할 수 있습니다. 특별한 도메인의 라이브러리는 직접 구현해야 할 경우도 있습니다.
- 오류 처리 부담: 예외(Exception)를 지원하지 않고 함수 리턴값으로 오류를 처리하는 방식을 취하기 때문에, 반복적인 오류 확인 코드가 많이 삽입되어야 하며, 이에 익숙해질 필요가 있습니다.

### 트러블 슈팅
1. 실행 오류
```
main.go:1:1: expected 'package', found 'EOF'
```
이 에러는 Go 컴파일러가 package 키워드를 예상했는데 파일이 비어 있다고(EOL, end-of-file) 판단한 경우 발생한다고 한다.
```
rm main.go
touch main.go
```
다음과 같은 명령어를 차례대로 적어준 뒤, 삭제된 파일의 코드를 옮겨적으니 실행이 되었다.

2. 실행 중 포인터 리시버 오류
```
# methodsAndInterfaces
./main.go:38:3: cannot use Product{…} (value of struct type Product) as Expense value in array or slice literal: Product does not implement Expense (method getCost has pointer receiver)
```
이 에러는 
- Product의 getCost 메서드가 포인터 리시버로 정의되었지만,
- 인터페이스에 값 타입(Product) 을 넘겨 인터페이스 구현에 실패하여 오류가 난 것이다.

포인터로 값을 넘기도록 수정해주니 제대로 실행되었다.
```
expenses := []Expense{
    &Product{"kayak", "waterSports", 275},
}
```
포인터 리시버에 대해 처음 사용하다보니 이런 오류가 발생했던 것 같다.
